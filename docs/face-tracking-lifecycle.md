# 人脸跟随的连接退出清理

通过 `robot.face_tracking.start()` 启动且应答成功的普通端侧跟随，由该 `WatcheRobot` 实例持有。退出上下文或调用 `robot.close()` 时，在 Device channel 关闭前发送一次 `ctrl.face_tracking.stop`，使用 `hold` 策略保留当前位置。

- 未启动、启动失败或已经显式停止的跟随，不在退出时再次停止。
- 停止请求最多等待 2 秒；设备失联或停止失败仍继续关闭连接。该清理属于尽力释放，失联时不能保证设备已经停止。
- 启动与清理由同一控制锁串行化；连接进入关闭状态后拒绝新启动。
- 预览会话继续复用原有清理路径。Daemon 不解析跟随命令，业务消息仍经 Application 的 Device channel。

配套 ESP32 的 `fix(camera): 在创建拍照任务前恢复快门音效资源` 独立合入 `dev`，用于媒体切换后的快门音恢复。设备切回 PTL 相机固件时不支持 SSCMA 推理和端侧跟随，应以设备能力上报为准。

回归覆盖上下文退出、重复关闭、未持有/显式停止以及停止超时后的连接释放。目标分支加入修复前有两项失败，修复后 Application 上下文、跟随和视觉相关 28 项测试通过。历史真机验证观察到跟随退出后由残留运行变为停止；此记录不替代长期失联和断电场景验收。
