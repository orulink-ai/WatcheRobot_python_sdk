# Watcher Expression Lab

这是 KuroBlob 风格代码表情的 SDK 实验台。浏览器只负责预览和调参；真正显示在
Watcher 屏幕上的画面由 ESP32 在本地生成，不传输逐帧图片，也不执行浏览器脚本。

正式 Application ID 为 `com.orulink.expression_lab`。当前应用广场版本只声明已经完成
真机验收的 Windows；macOS 在完成同等安装、启动、配对和真机渲染验证前不会标记为支持。
Watcher 固件必须提供 `expression.runtime.v3` 能力，DIY 矢量装饰还需要
`expression.vector_accessory.v1`。旧固件仍可安装 Application，但页面会明确提示先通过
Watcher Desktop 更新固件，不会静默黑屏或回退到 AnimPack。

## 运行

先启动 Expression Lab：

```powershell
watcherobot app run .\examples\expression_lab
```

macOS/Linux：

```sh
watcherobot app run ./examples/expression_lab
```

Application 会打开一个仅监听 `127.0.0.1` 随机端口的网页。点击“发送到 Watcher”
启动代码表情；之后拖动参数会实时更新。点击“退出实验”或关闭 Application 后，设备
会停止代码表情并恢复默认显示。

“鼠标追踪”默认开启。把鼠标移入表情画布后，Web 预览会平滑看向指针；“跟随幅度”
默认是 `1.45×`，可在 `0.60×`–`2.00×` 之间调整。代码表情已在 Watcher 上运行时，
同一组 `gaze_x` / `gaze_y` 会限频合并更新同步到实机。鼠标移出画布后视线平滑回到
中央。关闭“鼠标追踪”即可恢复水平、垂直视线滑杆。

视线参数达到 `-1.0` 或 `1.0` 时，Web 与 Watcher 的眼睛中心最多移动约 32 个物理
像素；旧实验版为 20 像素。大尺寸眼睛在极限位置可能接近画布边缘，这是预期构图边界。

如果页面显示“等待 Watcher”，在机器人上打开 **Desktop Link**，把屏幕显示的六位
配对码输入网页顶部的“屏幕配对码”，再点击“连接”。配对由 SDK Runtime 的设备管理
接口完成，网页不会直接访问串口或绕过当前 Application。

也可以直接双击 `web/index.html` 查看和调整本地视觉预览；这种方式不会连接设备，
页面会显示“仅本地预览”。需要把参数发送到 Watcher 时，必须使用上面的 SDK 命令启动。

## 固件升级闭环

Application `0.1.1` 内置了 ESP32 PR
[`orulink-ai/WatcheRobot_esp32#199`](https://github.com/orulink-ai/WatcheRobot_esp32/pull/199)
提交 `c4807d1a0b7d912ea05abcb578b10f5d7ea0a2e4` 的完整 32MB 分段固件包。
页面检测到 Watcher 已连接、但缺少 `expression.runtime.v3` 时，会显示“下载固件包”按钮；
正常固件不会显示升级卡片。

升级步骤：

1. 在 Expression Lab 下载固件 ZIP，不要解压。
2. 打开 Watcher Desktop 的“创作者模式 → 固件与资源”。
3. 把 ZIP 拖入 ESP32 固件的本地安装包区域（也可点击该区域选择文件）。
4. 用数据线连接 Watcher、选择设备串口并开始安装。

内置包大小为 `4,159,343` 字节，SHA-256 为
`212026ebb365458a99fbc8d8c1e914244ed05a2c7815bd16ed8918fee0b7bada`。
Application 启动时会同时核对文件大小和 SHA-256；校验失败时不会提供下载。Watcher
Desktop 在安装前还会再次检查 ZIP 的 `flash_args.txt`、必要分段和 Flash 参数。

## 当前实验边界

- 画布：设备端原生 412 × 412 RGB565，直接对应屏幕物理像素；不再对代码表情做 206 → 412 最近邻放大。
- 目标刷新率：20 FPS。
- 预设：`standby`、`thinking`、`speaking`。
- 样式：Watcher 默认、紧凑、专注、开阔、脉冲。
- 参数精调：所有滑杆都会自动配套数字输入框，可用滑杆粗调，也可直接用键盘输入精确数值；两种输入会同步更新 Web 预览与设备参数。
- 眼皮预设：不再内置固定情绪形态。用户可将当前四块眼皮的位置与旋转命名保存到浏览器本地，之后在眼皮模块中直接调用或删除。默认上下眼皮退到 `-80 / 80`，不遮挡眼睛。
- 每只眼睛具有独立的上/下眼皮遮罩，共四块；每块可调整纵向位置（`-80`–`80` 逻辑像素）和旋转（`-45°`–`45°`）。
- 眼皮只遮盖眼睛颜色像素，不会擦除 Tag 或装饰；加宽遮罩可覆盖最大旋转角度下的眼睛外沿，并按左右眼半区裁切，避免跨眼误遮；眼皮随视线移动并使用平面渲染。
- 标签：无、思考、问号、爱心。
- 装饰：无、天使光环、恶魔红角、忍者面罩、英雄面罩、海盗眼罩、UFO 天线。
- DIY 矢量路径 V1：提供 `412 × 412` 物理像素坐标画板、圆头画笔、局部橡皮、`4`–`24 px` 线宽、撤销/重做和清空。它是面向手绘装饰的受限折线路径，不支持任意 SVG、贝塞尔命令、填充图形或浏览器脚本。
- 矢量路径最多 `12` 条笔画、每笔最多 `48` 个节点、总计最多 `192` 个节点。浏览器在抬笔时自动简化采样点，并显示当前笔画/节点占用；ESP32 只解析有版本、长度和坐标边界校验的紧凑路径数据。
- 矢量图案可以放在眼睛前方或后方，并继续使用装饰模块的缩放、横向/竖向位置和旋转。表情跟随鼠标时，图案沿用装饰的约 50% 位移，避免与眼睛割裂又不过度偏移。
- 完成一笔并松开鼠标后才会向 Watcher 合并同步一次；绘制过程不连续发送，避免手绘时造成实机卡顿。单次矢量装饰最多传输约 `794` 字节的路径数据，之后由 ESP32 本地逐帧绘制。
- 矢量图案可命名保存为个人预设，最多保存 12 个；预设保存在当前浏览器的本地存储中，清理浏览器数据或更换电脑后不会自动迁移。
- 装饰可独立调整缩放（`0.25`–`2.0`）、横向/竖向位置（`-1.0`–`1.0`）与旋转（`-180°`–`180°`）。
- 内置装饰由设备端白名单绘图实现；DIY 装饰只发送经过严格边界校验的有限折线路径，不向设备发送或执行任意 Canvas/JavaScript/SVG 代码。
- 当前实验固定使用平面渲染并发送 `sphere_strength=0`，不再显示或计算球面投影。
- 眼睛、眼皮、标签与装饰模块标题栏均提供“恢复默认”，实验运行中也会同步恢复实机参数。
- 鼠标追踪是二维视线参数控制，不传输画面；约 55 ms 采样、90 ms 过渡。
- 浏览器预览用于设计对照，最终性能和像素效果以真机为准。
- 代码表情运行时不会读取 AnimPack；Web 工作台只提供矢量画板。固件暂时保留旧像素协议能力用于已发布 SDK 的向后兼容，但新版页面不会再发送该数据。

眼睛分段几何改编自 MIT 许可的 KuroBlob-AI Watcher renderer；许可证见
`KUROBLOB_AI_LICENSE.txt`。
