## 目标与范围

桌面安装 v0.0.10 官方 SD 资源时，在第一个内容寻址 action 的 `.json.part` 路径报 Errno 22。排查和修复源码归 SDK 的读卡器安装器，保持官方资源校验、可恢复安装和用户作品保护；不复制 Daemon、不改变业务路由，不格式化或修复用户文件系统。

## 调查记录

- 实际失败路径由 `runtime/daemon/maintenance/card_reader.py::_extract` 生成。该路径没有 fsync 调用，不能按 fsync 兼容问题处理。
- 系统卷为 FAT32，约 120 MiB；USB VID 05E3 / PID 0747，Generic STORAGE DEVICE。只读 chkdsk 报文件与目录检查无问题，未使用 `/f`。
- 新建唯一私有目录的短名、64 字节 SHA-256 名称、`.json.part`／`.animpack.part` 写入及读回均通过；实际 action 目录中的同名小探针也通过；仅删除自己创建的探针。不存在即可删除 `.part` 也通过。暂不能确认长文件名为根因。
- 原有用户作品仍在，不读取作品内容到日志。后续对写卡前后作品做哈希验证。

## 验证计划

先最小复现真实异常与栈，再增加对应失败测试、实现修复及回归。未复现前不臆测原因，不宣称完成。

## 根因与本轮修复

- 真实最小副本提取在 `_extract` 的 `os.replace(temporary, target)` 报 Windows 1117（I/O 设备错误），不是 fsync；长文件名写入本身和若干重命名可以成功，不支持“长文件名恒不兼容”的结论。
- 随后只在独占探针目录创建子目录时出现损坏不可读；只读磁盘检查报告该新目录分配单元无效。已停止对异常卷的写入，未执行格式化或修复；具体是卡、读卡器、接触还是连接尚不能区分。用户确认使用独立 USB 读卡器。
- 软件缺陷是未在清理旧官方数据前验证基本原子写入，且维护界面只得到裸 OSError。现增加独占临时目录的写入／重命名／读回预检，预检失败保留旧资源；对安装中 OSError 包装可操作的诊断，保留原异常与 Windows 错误码，不自动重试或关闭校验。
- 当前说明见 [SD 读卡器安装与排障](../../../../docs/sd-card-installation.zh-CN.md)；README 和排障表已更新。没有找到本仓更早的独立 SD 安装档案，不伪造历史链接。
