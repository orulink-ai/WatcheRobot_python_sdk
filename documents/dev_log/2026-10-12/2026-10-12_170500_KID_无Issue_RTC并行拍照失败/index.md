## 实机证据

用户截图对应 16:54:08 后端 `TimeoutError: camera capture did not return a JPEG before timeout`。16:54 前后 RTC 媒体统计继续增长，没有断开。

机器人串口复现：摄像头请求 session=2 获得 ACK，但初始化时 DMA 可用约 4 KB、最大块约 3 KB。SSCMA 需要 4096 B 连续内部 DMA 缓冲，报 `no mem for SPI DMA buffer`，HAL/CAMERA_SVC 初始化失败，完成结果 -6（ESP_FAIL）。SDK 忽略已有 `evt.sdk.camera.capture` 失败事件，等待 JPEG 超时。页面误导为连接问题。

### 用户确认设备应使用 PTL

用户指定 `yarn esp32:ptl:full` 配端口。停止测试通话后，使用 ESP32 端口（自动匹配配套 Himax）执行 `yarn esp32:ptl:full -Port <ESP32 串口>`，按当前源码构建并配套烧录。PTL 设备不能继续以 SSCMA 内存优化作为本次解决方向。配套烧录已成功，ESP32 写入后 hash 校验通过，设备管理查询确认 v0.5.5。未宣称照片已恢复。

保留 SDK 失败事件处理：即使后端配套正确，真实摄像头或上传失败仍应及时告知用户，不能伪装为连接异常。应用只依赖已有 WatcheRobotError 基类以保持旧 SDK 可启动，旧 SDK 未消费失败事件时仍有明确照片超时提示。


### 2026-10-12｜KID / Codex｜演示范围收敛与 PTL 回归

用户决定演示聚焦全双工 RTC，默认关闭拍照。先增加 3 项语义 Red：缺少相机能力仍被拒绝、默认状态无功能开关、没有显式启用参数。实现后，同一用例与服务生命周期合计 76 项通过；SDK API / 示例 / RTC 合计 246 项通过。服务默认不注册拍照和照片下载接口，页面隐藏拍照区并收为单列，相机 SDK 与可选开发路径保留。

PTL 配套流程前两次在设备写入前失败：构建期间外部会话切换 ESP32 checkout，随后新版固件入口不再接受历史 ConfigureJoyInside 参数。未恢复或覆盖另一会话源码；工作区三个 adapter 按被调用脚本的真实参数表决定是否转发该参数，同步维护两平台薄入口、文档和回归。新协议参数泄漏用例先失败 3 项，修正后 7 项通过；工作区 ESP32 workflow 测试通过。完整配套流程最终 exit=0，构建当前 v0.5.5 PTL，并写入 ESP32 bootloader / 分区 / OTA 初始数据 / 应用 / 模型 / storage。纠正文档中旧的“不会刷新”描述。未修改固件源码。

当前 v0.5.5 的无拍照 RTC 实测两轮均先连接、双向媒体包增长（浏览器报告 lost=0），随后约 10 秒触发 ICE disconnected，页面执行 browser_failure 并释放资源。串口同时记录内部可用内存最低约 2.1 KB、DMA 可用最低 26 B，以及 PeerConnection 循环超过 100 ms。第三轮再次见断开；第四轮用于中英文实时切换，在 connected 状态切换两种语言、保留静音，随后主动结束，不能算持续稳定性通过。

关闭拍照不解决这一独立通话问题。内存紧张与调度迟滞是调查证据，尚未通过对照实验证明唯一根因；新固件与此前验收源码存在差异，不能沿用旧结果宣称稳定。后续需定位固件资源预算、显示与媒体任务的竞争。本次没有通过重连掩盖掉线，没有扩大 Daemon 业务路由。
