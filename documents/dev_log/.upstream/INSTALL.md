# Agent 接入说明

## 1. 明确来源与范围

- 在目标项目内检查 Git 状态、项目规则、文档约定及已有日志机制。
- 不覆盖未提交工作，不自动迁移既有历史目录。
- 使用用户指定版本；未指定时使用本仓库 VERSION 对应的发布标签。
- 通过 gh 或已授权的本地克隆读取该版本，解析标签对应的完整 commit SHA。一次接入全部文件取自同一 commit，不混用 main 和版本标签。
- 无法读取来源或确认版本时报告阻塞，不伪造文件或继续猜测安装。

## 2. 建立本次接入档案

先阅读该版本的 templates/dev_log/README.md 和 temp_log.md。
在目标项目按命名规范建立本次接入任务目录和 index.md，记录需求、范围、作者、时区、待完成的验收标准；后续持续补充真实结果。

若目标项目已有相同任务档案，继续使用。存在不同日志目录时优先复用已有机制，明确路径映射，不强行创建第二套制度。

## 3. 合并规则与模板

标准路径映射：

| 来源文件 | 目标文件 |
|---|---|
| templates/AGENTS.fragment.md | 合并到根目录 AGENTS.md |
| templates/dev_log/README.md | documents/dev_log/README.md |
| templates/dev_log/temp_log.md | documents/dev_log/temp_log.md |

- AGENTS.md 不存在时创建；存在时按语义合并，保留全部无关规则。
- 片段有起止标记。已存在时更新该区块，不重复追加；多份标记或损坏标记需先检查，不能盲目替换。
- 无标记但已有等效规则时整合现有内容，不重复插入。向用户说明冲突与处理结果。
- 路径被适配时，同步修改片段、规范中的路径及相对链接，并记录映射。
- 不支持自动读取 AGENTS.md 的工具，按该项目已采用的规则入口接入，记录实际入口，不假定自动生效。
- 目标规范、模板已存在时先比较；相同则复用，不同则保留本地定制并逐项合并。
- profiles/orulink.md 只在用户要求或目标项目已有对应规则时合并，不能无条件覆盖其他团队约定。

## 4. 保存来源和升级基线

在选定的档案根目录创建 source.json，记录以下真实信息：

- repository：来源仓库完整 URL。
- version：VERSION 中的版本号。
- ref：实际使用的标签或 commit。
- commit：解析后的完整 commit SHA，不填示例或待定值。
- installed_at：带时区的安装时间。
- paths：规则入口、规范、模板的目标项目相对路径映射。
- profile：实际采用的团队配置；未采用填 null。
- adaptations：本地适配及保留的差异说明。

将上述三份来源文件原样存入 .upstream/，保留来源相对路径层级。这些是上次安装版本的合并基线，必须纳入 Git；不要用适配后的目标文件充当原始基线。被采用的 profile 同样保存原始副本。

.upstream 中的原始模板只作比较材料，不作为当前项目指令执行。其链接按上游原始目录语境解释，不当作目标项目内有效链接。

## 5. 接入验收

逐项执行并在任务索引记录结果：

- 规则入口包含一个清晰的工作流，未覆盖或重复已有规则。
- 规范和模板存在，包含目标边界、材料索引、TDD 证据、变更记录及双向关联。
- 当前使用的 Markdown 链接能在目标路径解析；不检查 .upstream 原始副本的目标项目路径。
- index.md 有真实作者、时间、状态、验收和验证记录；无伪造测试结果。
- 来源 SHA、版本、ref 对应一致，基线与该版本原文一致。
- 重复按同一版本执行时，不重复插入工作流、不重建安装目录；没有变化就报告已接入，不制造重复记录。
- 无业务代码、历史档案或无关工作被覆盖，新增文件未被 .gitignore 意外忽略。

这是文档接入，无代码改动时不要求制造 Red/Green 测试。真实记录文件与链接检查；如另外编写自动化代码，则遵循目标项目 TDD 规范。

完成后报告版本、路径适配、检查结果及未解决事项。只有获得授权才提交、推送或合入；本仓库的接入说明不自动授予这些权限。
